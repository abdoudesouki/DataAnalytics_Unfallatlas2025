Clustering traffic accidents with injuries – Germany 2025 (Unfallatlas)¶

Goal: Cluster all accidents with injuries into 3 clusters with three algorithms and check whether the clusters match the actual accident category UKATEGORIE (1 = killed, 2 = seriously injured, 3 = slightly injured).

Algorithms: K-Means, Gaussian Mixture (GMM), Agglomerative (Ward).

Accuracy: Clustering gives no label names, only cluster numbers 0/1/2. Each cluster is therefore matched one-to-one to a category so that the most accidents are correct (Hungarian algorithm). Then accuracy = share of accidents whose cluster matches their category.

2. Features ¶

Table of Contents

  • Accident attributes: kind (UART), type (UTYP1), light, road condition and the involved road users. Categorical columns are one-hot encoded (0/1).
  • Time (proxy for traffic density): hour (USTUNDE), month (UMONAT) and weekday (UWOCHENTAG). They are cyclic (23:00 is next to 0:00, December next to January), so each is encoded as a sine/cosine pair. This keeps them in the range -1…1, similar to the 0/1 columns, and adds only 6 columns.
  • Location, IDs and coordinates are not used. The label UKATEGORIE is not used for clustering.

3. Helper: map clusters to categories and compute accuracy ¶

Table of Contents

In [4]:
labels = {1: 'killed', 2: 'seriously injured', 3: 'slightly injured'}

def evaluate(y_true, clusters):
    # confusion table: rows = actual category, columns = cluster
    ct = pd.crosstab(y_true, clusters).reindex(index=[1, 2, 3], columns=[0, 1, 2], fill_value=0)
    rows, cols = linear_sum_assignment(-ct.values)          # best one-to-one cluster -> category
    mapping = {ct.columns[c]: ct.index[r] for r, c in zip(rows, cols)}
    y_pred = pd.Series(clusters).map(mapping).values
    acc = accuracy_score(y_true, y_pred)
    # chance reference: same cluster sizes, randomly shuffled
    rng = np.random.default_rng(0)
    shuffled = rng.permutation(clusters)
    ct_s = pd.crosstab(y_true, shuffled).reindex(index=[1, 2, 3], columns=[0, 1, 2], fill_value=0)
    r_s, c_s = linear_sum_assignment(-ct_s.values)
    chance = ct_s.values[r_s, c_s].sum() / len(y_true)
    ct.index = [labels[i] for i in ct.index]
    ct.columns = [f'cluster {c} -> {labels[mapping[c]]}' for c in ct.columns]
    return acc, chance, adjusted_rand_score(y_true, clusters), ct, y_pred

8. Conclusion ¶

Table of Contents

  • All three algorithms reach only about 39–51 % accuracy. That is the same as clusters of the same size chosen at random, and far below the trivial baseline of always predicting "slightly injured" (84.3 %).
  • The Adjusted Rand Index is ≈ 0 for all three, so the clusters are practically unrelated to accident severity.
  • Why: the algorithms group accidents by what is most different in the features (kind/type of accident, road users, and now also time of day, season and weekday), not by severity. Severity is heavily imbalanced (0.9 % killed, 14.8 % serious, 84.3 % slight), and in every feature group most accidents are "slightly injured". So no natural cluster can be "the killed accidents".
  • Accuracy here is computed with a one-to-one mapping (each cluster = one category). If each cluster were instead labelled with its most frequent category, every cluster would become "slightly injured" and accuracy would be 84.3 % – which just equals the baseline.
  • Clustering alone therefore cannot separate the accident categories in this form – see Part 2 for handling the imbalance.

Part 2: Dealing with the class imbalance (focus: killed) ¶

Table of Contents

Killed is only 0.9 % of all accidents. Three things are done:

  1. Better metrics – plain accuracy rewards ignoring killed. Use balanced accuracy (mean recall of the 3 classes, chance = 33 %) and, for killed: recall (share of fatal accidents found), precision and lift (precision ÷ 0.9 % base rate; lift 1 = no better than random).
  2. Balanced data – undersample seriously and slightly injured to the number of killed accidents before clustering.
  3. More clusters than classes – with k = 10 small "high-risk" clusters can form; each cluster gets the majority category (on the balanced data).

Clusters are fitted on a balanced training set and evaluated on a held-out test set with the real class distribution.

from sklearn.metrics import balanced_accuracy_score, recall_score, precision_score

def scores(y_true, y_pred):
    prec = precision_score(y_true, y_pred, labels=[1], average=None, zero_division=0)[0]
    return {'Accuracy': accuracy_score(y_true, y_pred),
            'Balanced accuracy': balanced_accuracy_score(y_true, y_pred),
            'Killed recall': recall_score(y_true, y_pred, labels=[1], average=None)[0],
            'Killed precision': prec,
            'Killed lift': prec / (y_true == 1).mean(),
            'Share flagged as killed': (y_pred == 1).mean()}

def cluster_and_map(algo, k, X_fit, y_fit):
    """Fit k clusters on X_fit, name each cluster with a category (using y_fit),
    return a function that predicts the category of new accidents."""
    if algo == 'Agglomerative' and len(X_fit) > 10_000:   # memory grows with n² -> random sample of 10,000
        s = np.random.default_rng(42).choice(len(X_fit), 10_000, replace=False)
        X_fit, y_fit = X_fit[s], y_fit[s]
    if algo == 'K-Means':
        m = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X_fit)
        c, assign = m.labels_, m.predict
    elif algo == 'Gaussian Mixture':
        m = GaussianMixture(n_components=k, random_state=42).fit(X_fit)
        c, assign = m.predict(X_fit), m.predict
    else:   # Agglomerative has no predict(): assign new points to the nearest cluster centre
        c = AgglomerativeClustering(n_clusters=k, linkage='ward').fit_predict(X_fit)
        centres = np.array([X_fit[c == i].mean(axis=0) for i in range(k)])
        assign = lambda Z: pairwise_distances_argmin(Z, centres)
    ct = pd.crosstab(c, y_fit).reindex(index=range(k), columns=[1, 2, 3], fill_value=0)
    if k == 3:   # one-to-one mapping as in Part 1
        r, cc = linear_sum_assignment(-ct.values)
        mapping = {ct.index[i]: ct.columns[j] for i, j in zip(r, cc)}
    else:        # each cluster gets its majority category
        mapping = ct.idxmax(axis=1).to_dict()
    return lambda Z: pd.Series(assign(Z)).map(mapping).values

11. Conclusion on the imbalance ¶

Table of Contents

  • Accuracy is the wrong metric here. The 84 % baseline finds no fatal accident. Use balanced accuracy and killed recall/precision.
  • Balancing + k = 3 clusters: balanced accuracy 36–37 %, about 29 % of fatal accidents found, lift ≈ 1.3 – only slightly better than random.
  • Balancing + k = 10 clusters is somewhat better: balanced accuracy 39–41 %. Gaussian Mixture gives the highest lift (1.65); K-Means finds the most fatal accidents (52 %) but flags 38 % of all accidents.
  • The time features make the clusters worse, not better (K-Means k = 10: balanced accuracy 0.47 → 0.39, lift 2.4 → 1.4). The 6 time columns account for almost half of the total variance, so the clusters now mainly split accidents by time of day, season and weekday. The part of the time signal that matters for severity – night hours with low traffic – covers only ~3 % of accidents, too few to form a cluster of its own. Month adds variance with almost no link to severity. Repeating with 2 other random splits gave the same picture (with time: balanced accuracy 0.38–0.40, lift 1.3–1.6).
  • Even the best variants only narrow fatal accidents down to a group with a somewhat higher risk (killed precision 1–2 % vs. a 0.9 % base rate); they cannot separate them.
  • Oversampling with SMOTE instead of undersampling is tested in Part 4.
  • Possible next steps: give the time features less weight or use simple flags (night, weekend) instead of month/hour curves, and add location (e.g. rural vs. urban from coordinates or municipality).

Part 3: DBSCAN with grid search (exactly 3 clusters) ¶

Table of Contents

DBSCAN has no "number of clusters" parameter. It finds dense regions controlled by eps (neighbourhood radius) and min_samples (points needed in that radius). Points that belong to no dense region are labelled noise (-1).

Setup (same data as Part 2, so the results are comparable):

  • Grid: eps × min_samples, fitted on the balanced training set. Only combinations that give exactly 3 clusters are kept.
  • Noise: to keep exactly three groups, each noise point is assigned to the cluster of its nearest core point. New (test) accidents are assigned the same way, because DBSCAN has no predict().
  • Best parameters: highest balanced accuracy on the training set (clusters mapped one-to-one to categories as in Part 1). The test set is only used for the final evaluation.
  • Grid range: eps 0.5–2.5 (step 0.1) and min_samples 5–200 (step 5). A first coarse scan showed that exactly 3 clusters only occur in this range.

from sklearn.cluster import DBSCAN

def dbscan_3(eps, min_samples, X_fit):
    """Fit DBSCAN; return (n_clusters, noise share, function that assigns any data to the nearest core point's cluster)."""
    db = DBSCAN(eps=eps, min_samples=min_samples).fit(X_fit)
    n_clusters = len(set(db.labels_)) - (-1 in db.labels_)
    noise = (db.labels_ == -1).mean()
    cores, core_labels = X_fit[db.core_sample_indices_], db.labels_[db.core_sample_indices_]
    assign = lambda Z: core_labels[pairwise_distances_argmin(Z, cores)] if len(cores) else None
    return n_clusters, noise, assign

def map_3_clusters(y_true, clusters):
    ct = pd.crosstab(clusters, y_true).reindex(index=range(3), columns=[1, 2, 3], fill_value=0)
    r, c = linear_sum_assignment(-ct.values)
    return {ct.index[i]: ct.columns[j] for i, j in zip(r, c)}

def dbscan_grid_search(X_fit, y_fit):
    """Try all eps / min_samples combinations; score the ones with exactly 3 clusters on the training data."""
    grid = []
    for eps in np.round(np.arange(0.5, 2.51, 0.1), 1):
        for min_samples in range(5, 201, 5):
            n_clusters, noise, assign = dbscan_3(eps, min_samples, X_fit)
            row = {'eps': eps, 'min_samples': min_samples, 'n_clusters': n_clusters, 'noise share': noise}
            if n_clusters == 3:
                c = assign(X_fit)
                row['balanced acc. (train)'] = balanced_accuracy_score(y_fit, pd.Series(c).map(map_3_clusters(y_fit, c)))
            grid.append(row)
    return pd.DataFrame(grid)

def dbscan_best_predictor(grid, X_fit, y_fit):
    """Refit DBSCAN with the best 3-cluster parameters; return (best row, function that predicts categories)."""
    best = grid[grid.n_clusters == 3].sort_values('balanced acc. (train)', ascending=False).iloc[0]
    _, _, assign = dbscan_3(best.eps, int(best.min_samples), X_fit)
    mapping = map_3_clusters(y_fit, assign(X_fit))
    return best, lambda Z: pd.Series(assign(Z)).map(mapping).values

12. Conclusion on DBSCAN ¶

Table of Contents

  • DBSCAN is not a good fit for this data. Small eps gives dozens to hundreds of tiny clusters, large eps merges everything into one cluster. Only 25 of 840 parameter combinations give exactly 3 clusters, and all of them label a large share of accidents as noise (about half for the best combination).
  • Best parameters (train): eps = 1.8, min_samples = 55. On the test set: balanced accuracy 0.38, only 32 % of fatal accidents found, lift ≈ 1.1 – about random, and not better than K-Means / GMM / Agglomerative.
  • Not stable: repeating the grid search with 4 other random splits picked very different parameters (eps 0.6–1.9, min_samples 10–80, noise 48–99 %), with test balanced accuracy 0.37–0.38 each time.
  • With the time features DBSCAN got worse than before (balanced accuracy 0.43 → 0.38) for the same reason as the other methods.
  • Note: choosing the parameters with the labels (balanced accuracy on the training set) is a form of supervision. Without labels, DBSCAN would give even less reason to pick these settings.

Part 4: SMOTE oversampling instead of undersampling ¶

Table of Contents

Undersampling (Parts 2–3) throws away ~97 % of the training accidents. SMOTE does the opposite: it keeps all real accidents and creates synthetic killed and seriously injured accidents until every class is as large as slightly injured. A synthetic accident is placed between a real accident and one of its nearest neighbours of the same class.

  • SMOTENC (SMOTE for mixed data) is used: plain SMOTE would interpolate the one-hot columns and create impossible values (e.g. "40 % leaving the road to the right, 60 % to the left"). SMOTENC interpolates only the time columns and gives the categorical columns the most common value among the neighbours. The result is then one-hot encoded as before.
  • SMOTE is applied to the training set only. The test set is the same untouched one as in Parts 2–3 (real class distribution).
  • Agglomerative clustering and DBSCAN cannot handle ~480,000 rows (memory/time), so they use a random sample of the SMOTE data (10,000 rows for Agglomerative as in Part 1; 5,202 rows for DBSCAN, the same size as the undersampled set).
  • Requires pip install imbalanced-learn. Runtime: this part takes ~12 minutes (SMOTENC ~5 min, Gaussian Mixture k = 10 ~5 min).

15. Conclusion on SMOTE ¶

Table of Contents

  • SMOTE balances the training set to 161,069 accidents per class. 98.9 % of the killed accidents are synthetic – they are all built from the same 1,734 real fatal accidents. SMOTE adds no new information about fatal accidents, only more points between existing ones.
  • Results on this split are mixed:
    • k = 3: practically identical to undersampling (balanced accuracy 0.36–0.37, lift ≈ 1.3).
    • K-Means k = 10 (0.39 → 0.41, lift 1.4 → 1.9), Agglomerative k = 10 (0.39 → 0.41) and DBSCAN (0.38 → 0.40, lift 1.1 → 1.9) are slightly better,
    • Gaussian Mixture k = 10 is worse (0.41 → 0.38, lift 1.65 → 1.3).
  • Repeated with 3 other random splits, the differences are within the normal run-to-run variation: average balanced accuracy k = 3: 0.36 (SMOTE) vs. 0.36 (undersampling); k = 10: 0.41 vs. 0.40; DBSCAN: 0.38 vs. 0.37. Lift for k = 10 was slightly higher on average with SMOTE (1.7 vs. 1.5), but individual runs go both ways. DBSCAN's best parameters again changed from split to split (eps 1.5–2.0, min_samples 75–165, noise 50–92 %).
  • Why so little difference: clustering does not learn from the labels. Balancing only changes how much weight each class gets when the clusters are formed – undersampling and SMOTE both give the classes equal weight, so the clusters end up similar.
  • Cost: ~480,000 instead of ~5,200 training rows, ~12 extra minutes of runtime, and Agglomerative / DBSCAN still need a sample.
  • Overall: SMOTE does not solve the problem. The limit is the weak link between these features and accident severity, not the number of fatal accidents. For clustering, simple undersampling is as good and much faster.
